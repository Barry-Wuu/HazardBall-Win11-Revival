# 003 — 窗口模式鼠标坐标错位：光标分身 / 点哪都出界

## 现象

窗口模式下，把游戏窗口放到**屏幕中间**后：

- 屏幕**左上角残留一个鼠标分身**（真光标被拽到游戏窗口外）
- **点任何菜单都会跑到外面**
- 鼠标移动时**闪烁**（在边界反复被拽回）

## 根因

游戏的整套坐标**硬编码假设「客户区在屏幕原点 (0,0)」**。

### 证据 1：游戏主动要求窗口在原点

```
00423AD4  push esi                    ; lpParam
00423AD5  push ebx                    ; hInstance
00423AD6  push ebx                    ; hMenu
00423AD7  push 0x1E0                  ; nHeight = 480
00423ADC  push 0x280                  ; nWidth  = 640
00423AE1  push ebx                    ; Y = 0      ← ebx = 0
00423AE2  push ebx                    ; X = 0      ← ebx = 0
00423AE3  push 0x80880000             ; dwStyle
00423AF3  call [CreateWindowExA]
00423AF9  mov  [0x46FFBC], eax        ; 全局 HWND
```

窗口 X/Y **就是 0** —— 游戏本来就想待在屏幕左上角。

### 证据 2：clamp 边界是窗口内逻辑坐标

每帧 clamp `0x41C0D0`（由 `0x417EE4` → `0x413B06` 主循环调用）：

```
0041C0D0  sub esp, 8
0041C10B  call [GetCursorPos]                 ; 读【屏幕绝对坐标】
0041C111  fld  [0x44BC40]                     ; cursorX
0041C117  fcomp [0x4433A4]                    ; vs 25.0
0041C125  test ah, 1
0041C128  je   0x41C147
0041C12E  mov  [0x44BC40], 0x41C80000         ; 越界 -> 写回 25.0
0041C139  push 0x19                            ;   SetCursorPos(25, 当前Y)
0041C145  call esi
...
0041C14D  fcomp [0x4433A0]                    ; vs 600.0  (X 上界)
...
0041C180  fcomp [0x4433A4]                    ; vs 25.0   (Y 下界)
...
0041C1B0  fcomp [0x44339C]                    ; vs 440.0  (Y 上界)
```

`.rdata` 常量：

| 地址 | 值 | 含义 |
|---|---|---|
| `0x4433A4` | `25.0` | 下边距 |
| `0x4433A0` | `600.0` | X 上界 = 640 − 40 |
| `0x44339C` | `440.0` | Y 上界 = 480 − 40 |

**这三组值是 640×480 客户区的「窗口内」逻辑框，完全不含窗口屏幕原点。**

### 证据 3：窗口居中后 clamp 整体偏到窗口左侧

运行时实测（`ReadProcessMemory` + `ClientToScreen`）：

| 项 | 值 |
|---|---|
| 窗口客户区 | `638 × 478` |
| 客户区屏幕原点 | `(401, 241)` |
| clamp 期望区间 | `X[25, 600]` ← **整体在窗口左侧** |
| 实测 OS 光标 | `(247, 392)` ← 窗口左边界是 401，**光标在窗外 154 px** |

光标可跑到 `x=25`（窗口外 376 px）＝左上角分身；
向右被卡在 `x=600`（窗口右侧 439 px 点不到）＝点哪都出界；
在边界反复穿越＝**闪烁**。

### 为什么全屏没事

全屏时客户区就是整个屏幕，原点 `(0,0)`，**窗口内坐标 ≡ 屏幕坐标**，假设天然成立。
这是典型的「按全屏思维编写、窗口模式未做坐标转换」老游戏通病。

## 解法（已定案）

**让窗口待在 (0,0)** —— 游戏的原生要求。

`dgVoodoo.conf` 保持默认 `CenterAppWindow = true`：实测 dgVoodoo 在本作
**不会**强制覆盖游戏指定的初始位置，窗口稳定停在 `(0,0)`。
已连续重启 3 次验证：窗口均在左上角、菜单可正常点选。

> **窗口能否居中？**
> 可以，但需补一层坐标转换（hook `GetCursorPos`/`SetCursorPos` 做 ±`clientOrigin`），
> 使游戏内部「客户区坐标 ≡ 屏幕坐标」的假设在窗口模式下也成立。
> 本次曾尝试三版**窗口相对化 clamp 补丁**均未生效 —— 因为菜单命中检测是
> **另一处独立的 (0,0) 假设**，只改 clamp 不够。
> 工具链已就绪（`tools/hdis.py` / `refs.py` / `relcall.py`），
> `.theta` 段 `0x4748D9` 起有约 1.8 KB RWX 空闲可放 trampoline。

## 排查过程中纠正的三个错误结论

### 1. 误按标题匹配窗口

用 `GetWindowText` 枚举窗口时，抓到同名的
`CabinetWClass`「Hazard Ball」**文件选择对话框**（`1455×927`，pid ≠ 游戏进程），
据此误判「窗口在左上角」。

**正确做法**：用 `class='winclass'` + 客户区尺寸（`638×478`）过滤，
并用 `QueryFullProcessImageNameW` 校验进程名（参见 `tools/pin_window.py`）。

### 2. 误判 recenter 是干扰源

静态看 `0x40EB10` 每帧都在 `SetCursorPos`，像是与 clamp 打架的元凶。
但实测 `[0x44BC58]` / `[0x44BC5C]` **全文件无任何写入点**，恒为 `0` ⇒
recenter 目标 = `X + 0.03 × 155 × 0 = X`，**是空操作**。

「闪烁」实为 clamp 在居中窗口下频繁触发的**固有行为**，与补丁无关。

### 3. 只改 clamp 就以为能修好

改 clamp 边界后菜单依然点不动 → 证明菜单命中检测是独立的 (0,0) 假设。

## 方法论教训

**窗口/坐标类问题，先跑实机窗口枚举 + 读运行时全局，再动手。**

| 手段 | 能回答 | 不能回答 |
|---|---|---|
| 静态反汇编 | 代码**写了什么** | **实际发生了什么** |
| 实机窗口枚举 | 窗口真实位置/尺寸/类名 | — |
| `ReadProcessMemory` | 全局变量运行时真实值 | — |

本案的转折点正是运行时读数：`clientOrigin=(401,241)`、`[0x44BC58]=0`、
输入对象字段布局 —— 一次就把问题定性了。

## 附：运行时全局速查

| 地址 | 类型 | 含义 |
|---|---|---|
| `0x46FFBC` | `HWND` | 全局窗口句柄（仅 `0x423AF9` 写一次，其余 8 处只读，可靠） |
| `0x44BC2C` | `ptr` | 输入对象（见 `002` 文档） |
| `0x44BC40` / `0x44BC44` | `float` | 光标 X / Y（**屏幕绝对坐标**） |
| `0x44BC50` / `0x44BC54` | `dword` | clamp 边沿标记 |
| `0x44BC58` / `0x44BC5C` | `dword` | recenter 乘数（**恒 0**） |
| `0x44B46C` | `float` | 鼠标灵敏度（运行时在 0.015~0.03 间变化） |
| `0x463408` | `dword` | 游戏状态（主菜单 = 1，Tilt 模式 = 25） |
| `0x44BD4C` | `dword` | clamp 每帧置 `0x2D` |
| `0x44BD34/38/3C/40` | `dword` | clamp 每帧清零 |

> ⚠️ `0x44BC40/44` 被**几十处 UI 代码**改写为**游戏逻辑坐标**（400/480/720/320/180…）。
> 只有在「recenter 刚跑完 → clamp 紧随」这一帧窗口内才稳定是屏幕坐标。
> 判断语义时必须考虑时序，不能只看单点。
